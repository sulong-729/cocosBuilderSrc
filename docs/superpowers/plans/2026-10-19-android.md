# Android APK Implementation Plan

Goal: Add an Android page alongside iOS with selectable local tools, Cocos configuration, emulator/device management, APK build/install/run and logcat.
Architecture: android_backend.py owns discovery, profiles, processes and Android commands; android_panel.py owns asynchronous Qt UI; BuildConfigPanel is extended with a platform argument to own editable Android settings. Existing iOS stays in its page and shares the project sidebar.
Spec: docs/design/android-support.md
Execution: inline in the current checkout, as requested by the user. Preserve existing uncommitted log/window edits. No publishing or installer deployment.

- [x] Backend: write failing tests for Android-only profiles, package merge, duplicate Studio discovery, tool validation, device parsing, serial targeting, cancellation and APK selection; implement and verify.
- [x] UI: implement tool/profile forms, ordered platform tabs, project isolation and busy guards; add offscreen tests covering Android-only project selection and persisted settings.
- [x] Devices: AVD creation/start/stop/delete, USB and wireless connection, explicit adb targets; destructive actions require UI confirmation.
- [x] Pipeline: export with Creator, selected SDK/NDK/JDK environment, Gradle APK, metadata/ABI validation, installation, launch resolution, logcat restart tracking and cancellation. Verify with fixtures before touching a real project.
- [x] Integration: update packaging manifests, docs and run all existing tests; inspect actual Qt UI, local Android tools and available devices. Report native verification boundaries precisely.

Review focus: unauthorized/offline devices, old Cocos/Gradle with modern Java, task IDs shared by platforms, stale APK after failed builds, worker completion after project switches, secrets in config logs, shutdown during work.
Ledger: user explicitly selected APK only. No AAB or new release-signing UI. A missing Android task must explain how to create one rather than blocking the Android page itself. Existing iOS build lock and Android output lock keep output ownership independent; UI disallows simultaneous iOS/Android builds in one window.
